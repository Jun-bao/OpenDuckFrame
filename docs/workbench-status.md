# OpenDuckFrame 能力工作台开发快照

## 2026-11-03：品牌与采集尺寸更新

- 正式品牌为 **OpenDuckFrame**，中文昵称为“开源小鸭”。应用、关于窗口、17 种语言的产品名、Quick Look 和构建产物名称已统一，使用新的黄色鸭子图标。
- 2026-11-03 起 bundle ID、可执行名、配置路径、单实例锁、模块名和环境变量都改为 OpenDuckFrame 自己的标识（`app.openduckframe.*`、`ODF_*`、`--odf-*`），版本号从 0.1.0 开始。旧版的设置不会自动迁移。
- Release 候选 ODF2 已独立核对源码、包清单和签名，并在真实工作台检查名称、图标、中英文和长标题显示。首次原生检查发现的标题裁切已修正，最终截图可完整显示名称。
- 采集尺寸改为窗口尺寸稳定 300ms 后原地更新同一 SCStream 配置，不依赖下一帧触发，不改变采集代次。旧版压缩反例、修复后的真实缩小和放大、面板量尺及尺寸重启保留已取得有效证据；两轮新尺寸首次被日志看到的上界约 0.4 秒，底部与右侧死区均为 0。
- **采集几何整单尚未全部通过。** 处理器重建的现有两阶段语义让配置号增加两次，转换期 FPS 有未知值，Chrome 拖动、原生全屏、真 120 帧和 Retina 等剩余项未完整验收。部分压力测试仅验证采集更新与持有帧稳定，未取得有效物理呈现段。没有把这些项改写为通过。
- 本轮没有增加新的性能结论。已有两个未使用本地化键仍使完整本地化卫生检查失败，基线和本轮结果分别保留。源码检查、品牌/图标检查、Release 构建、单实例策略和实际锁检查通过，不代表所有检查均通过。
- 仓库改名、公开可见性、正式发行、签名公证和全量依赖/模型分发许可核查不在本轮完成范围。此开发快照不能视为全面验收的公开发行版。

## 当前范围

- 输入源：窗口、显示器、视频文件。采集卡通过 OBS 等预览窗口接入。
- 超分与插帧独立选择；包含 Apple FRC、Apple 低延迟插帧、RIFE，以及具备条件的实验引擎。
- 支持固定目标帧率与 X2/X3/X4 倍率设置，实际可用相位、尺寸和后端能力按运行环境判断。
- 工作台配置、中英文、外观、应用前倒计时和输出 HUD 等改动在本次源码中。

## 历史问题与验收边界（保留，未在本轮重新复验）

- 当前低延迟路径已经有实际插帧和用户报告接近两倍帧率的证据，但用户仍报告画面发糊、清晰与模糊交替，画质未通过。
- 最近一次实际生效的是 Apple 低延迟 X2，源 2560×1440 经 Lanczos 前置缩到 1920×1080，再铺回目标画面。该处理会损失原始细节；不能把它叫作原尺寸 FRC 复验。
- 在 Apple M5 Max / macOS 27.0.1 上的纯 Apple SDK 1080p NV12 对照中，绕过本应用的缩放、颜色转换与显示，合成高频图案仍存在细节差。它不能证明所有内容、所有引擎都存在同样程度的问题，也没有定位闭源后端内部环节。
- GPU 资源生命周期和共享顶点数据的修正已做组件核验；这不等于用户看到的交替模糊已解决。
- 固定 FPS、X3/X4、文件画面/音画、各引擎组合和剩余页面回归仍需按真实路径继续验收。离屏组件通过不代表物理呈现、持续 120 FPS 或整体交付完成。
- 上述诊断阶段曾暂停应用修改；此后开发已继续。原始失败与诊断结论继续保留，不以本轮品牌验收代替相应复验。该源码快照不是已全面验收的发行版。

## 获取与构建

```sh
git clone https://github.com/Jun-bao/OpenDuckFrame.git
cd OpenDuckFrame
./Apps/Mac/Scripts/build.sh Debug
```

需要匹配的 Apple 开发工具链。具体构建依赖见根目录 README 的 Build from source；Apple 新增能力还取决于系统与设备支持。

仓库包含源码、第三方源文件/声明、模型资源和测试脚本。构建产物、生成依赖、测试媒体、用户配置、账号凭据和本机原始运行日志不纳入 Git；运行时依赖按现有脚本构建或获取。

首次私有导入时曾关闭 Actions。公开整理后的检查入口和完整构建触发方式见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
